5. ISSUES FOUND (BRUTALLY HONEST — ALL SEVERITY)
================================================================================

**CRITICAL / BLOCKING FOR RELIABLE USE (must fix before Phase 2 or 0.3 stable):**

1. **CLI sensitivity + sensitivity-multi completely broken** (AttributeError on
   every invocation):
   cli.py:169 and :536: service.get_reference().get_all_regions()
   ReferenceData has no such method (it has list_available_lifts(),
   list_available_regions_for_lift(), estimate_moment_arm(), etc.).
   Fallback to KNOWN_MUSCLE_REGIONS is unreachable. Direct service.sensitivity()
   works fine; this is purely CLI wrapper bug (copy-paste from wrong object).
   Impact: sensitivity-multi (flagship multi-var + geo feature) unusable via CLI.

2. **Missing import in cli.py → profile save-config crashes hard**:
   Line 314: LiftConfiguration(...) but import at top is only
   "from fiberforce.models import Subject, JointAngles, ExternalLoad"
   (LiftConfiguration is in models.lift and re-exported in models/__init__.py).
   Impact: One entire enhanced persistence subcommand unusable.

3. **Dedicated `fiberforce deadlift` and `fiberforce ohp` commands do not exist**:
   Heavily advertised in CHANGES.md ("New dedicated first-class commands"),
   docs, GAMEPLANS, etc. Current surface only has generic analyze/sensitivity
   with lift arg + profile run. No @app.command("deadlift") etc. in cli.py.
   Impact: Documentation lies; user confusion; feature incomplete from "wiring"
   phase.

4. **compare command produces useless 0.0 results for non-bench lifts**:
   Default --target "Sternal fibers" (CLI line ~200) never matches glute/upper
   fibers etc. in analyze results → force_a/b = 0.0, empty deltas.
   Service.compare itself works when correct target/region passed.
   Impact: CLI compare only reliable for bench.

**MODERATE / ANNOYING:**

5. **profile compare-runs / load-result have flaky discovery**:
   Naming conventions between save-result (run_id based) and the loader
   candidates + list_saved_runs don't always align in matrix runs. Some
   "not found" even when list-results shows the name. (Examples 08/09 also
   hit similar during their internal discovery.)

6. **analyze / sensitivity CLI always echo the requested --target even if the
   actual result region differs** (e.g., deadlift analyze reporting "Sternal
   fibers" in some matrix outputs while computing glute). Cosmetic + confusing.

7. **Service.describe() and some example banners still say "v0.2 wiring + v0.3
   prep" and ReferenceData version "0.2.1-..."** — minor labeling drift now
   that we are in 0.3.0-dev.

**MINOR / KNOWN (not new):**

8. Absolute force scaling bug (~100x low, cm vs m in peak_force.py) — documented
   everywhere, examples/tests all call it out. Relative trends trustworthy.
9. Geometric prototype limited (bench/squat only certain regions; others fall
   back). Expected pre-Phase 2.
10. Many pre-existing profiles/results left in ~/.fiberforce/ from examples
    (side effect of persistence demos; not a code bug).
11. One-off 0.0N "error" case in ex01 for deadlift lumbar (handled).
12. No deprecation warnings in our code; only matplotlib upstream.

No other crashes, import failures, or obvious rot found in 100+ live invocations.
